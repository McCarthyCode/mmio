# Runbook: Restore the CSP nonce with a Cloudflare Worker (#43)

## What prompted this

After #42 moved production to an App Platform static site, the browser console
on `mattmccarthy.io` showed:

> Content-Security-Policy: The page's settings blocked an inline script
> (script-src-elem) from being executed because it violates the following
> directive: "script-src 'self' https://cdn.jsdelivr.net
> https://static.cloudflareinsights.com"

The blocked script is Cloudflare's JavaScript Detections snippet
(`window.__CF$cv$params`, which loads
`/cdn-cgi/challenge-platform/scripts/jsd/main.js`). This is the same problem
as issue #1. Cloudflare's guidance there: "If your CSP uses a `nonce` for
script tags, Cloudflare will add these nonces to the scripts it injects by
parsing your CSP response header." The same page also says: "JavaScript
Detections is not supported with `nonce` set via `<meta>` tags." #6 solved
this with a per-request Flask nonce in a response header. #42 dropped the
header, because static sites can't set one, and moved the policy into a
`<meta>` tag.

## Where the script comes from

Every domain is a proxied CNAME in our Cloudflare zone pointing at
`mmio-zy37z.ondigitalocean.app` (see runbook 36). That's an Orange-to-Orange
setup: requests pass through our zone, then DigitalOcean's Cloudflare zone.

- **Our zone:** Bot Fight Mode is off.
- **Custom domain:** the script appears on `mattmccarthy.io`.
- **DO default domain:** the script doesn't appear on
  `mmio-zy37z.ondigitalocean.app`.

So it's most likely injected by DigitalOcean's zone for custom-hostname
traffic, and that's not a setting we control. The Worker works either way:

- **DO's zone injects (upstream of the Worker):** the script is already in
  the body when the Worker rewrites it.
- **Our zone injects (after the Worker):** Cloudflare reads the nonce from
  the header.

## What changed

- **`cloudflare/csp-worker/`** (new): a Worker routed on `mattmccarthy.io/*`
  and `www.mattmccarthy.io/*`. Non-HTML responses pass through. For HTML it:
  - removes the meta CSP;
  - adds a fresh nonce to every `<script>`;
  - sends the policy as a header with `'nonce-…' 'strict-dynamic'`;
  - sets `Cache-Control: private, no-store` and drops the `ETag`.
- **Why `'strict-dynamic'`:** the injected script creates a hidden iframe and
  appends a second inline script inside it. That inner script has no nonce
  and can't be given one by rewriting HTML. Tested without
  `'strict-dynamic'`, the outer script ran but the inner one was still
  blocked. With `'strict-dynamic'`, scripts created by a nonced script are
  trusted. Browsers that support it ignore the host allowlist, which is why
  every `<script>` gets the nonce, not just inline ones.
- **`app/templates/index.html`:** the meta CSP stays as the policy for the DO
  default domain and local dev. Its comment now says the Worker replaces it.
- **Docs:** `docs/deployment.md` explains the Worker and how to deploy it.
  `docs/runbooks/42.md` has a correction note.
- **`app/.python-version`** (`3.14`): the App Platform build log warned that a
  missing `.python-version` will become an error. It asks for the major
  version only.

## Deploying (manual, needs Cloudflare login)

App Platform doesn't deploy the Worker. After merging:

1. `cd cloudflare/csp-worker`
2. `npx wrangler login`. This authenticates as the zone owner's Cloudflare
   account.
3. `npx wrangler deploy`
4. In the Cloudflare dashboard, open Workers Routes for `mattmccarthy.io` and
   set the request-limit failure mode to **Fail open**. Past the Free plan's
   100,000 requests a day, requests skip the Worker and fall back to the meta
   tag. Only the Cloudflare script is blocked again in that case.

## Verify after deploy

- `curl -sI https://mattmccarthy.io/` shows a `content-security-policy`
  header with `'nonce-…'` and `'strict-dynamic'`. The nonce differs between
  requests.
- `curl -s https://mattmccarthy.io/` has no meta CSP. Its injected
  `<script>` carries the header's nonce.
- `/static/style.css` and `/robots.txt` have no CSP header, and keep
  `cache-control: public,max-age=10,s-maxage=86400`.
- The six redirect hosts still 301.
- In the browser console, there are no CSP violations, and
  `/cdn-cgi/challenge-platform/.../main.js` loads in the Network tab.

## Rollback

Remove the Worker routes in the dashboard, or run `npx wrangler delete` from
`cloudflare/csp-worker/`. The site goes back to the meta-tag policy: it works,
with the console error.

## Keeping the policy in sync

The policy lives in two places: the meta tag in `app/templates/index.html`
and `POLICY` in `cloudflare/csp-worker/src/index.js`. Any new script, style or
font host goes in both.
